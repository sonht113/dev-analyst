# ADR 0008: Phase 06 — Claude Code CLI explanations

Status: accepted for the owner's explicit Phase 06 request. Retain the confirmed DevAnalyst identity and `@devanalyst/ai`, rather than creating the historical prompt's `@devlens/ai`. Scope remains React + Vite. This implements the Node provider API, not browser dispatch, pre-analysis, persistent caching or another framework.

## Research and compatibility

Use the installed native Claude Code CLI, not an Anthropic SDK or an assumed API entitlement. The [CLI reference](https://code.claude.com/docs/en/cli-reference), [programmatic usage](https://code.claude.com/docs/en/headless), [permissions](https://code.claude.com/docs/en/permissions), [settings reference](https://code.claude.com/docs/en/settings-reference) and [environment reference](https://code.claude.com/docs/en/env-vars) informed the implementation. Local `claude --version`/`--help` and a synthetic non-interactive invocation verified the installed 2.1.323 flag surface and stream shape. Safe/restricted mode retains native CLI authentication; bare mode deliberately does not use subscription OAuth/keychain, so it is unsuitable for this adapter's account compatibility.

The supported release is **exactly 2.1.323 on macOS/Linux with a native executable**. Other releases fail closed until their capabilities, structured output and permission behavior are verified and tests updated. Windows command/batch wrappers, custom gateways and Bedrock/Vertex/Foundry routing are unsupported. The provider does not install/update Claude, log in, copy credentials, invoke an SDK, request permission bypass, or silently switch credential destinations.

`checkReadiness()` separates executable/version/capability detection, CLI auth status and non-interactive inference. Auth status alone leaves inference `unverified`; `checkReadiness({probe:true})` uses an explicitly enabled, bounded synthetic Japanese greeting to check the actual configured model/account. A successful probe is a timestamp-local capability observation, not a promise of future quota or availability. Existing CLI login does not establish access to every model/API/SDK. Raw identity, email, tokens, account metadata and provider diagnostics are not exposed.

## Runtime enforcement and trust boundary

- Resolve an executable with X_OK, pin its canonical path and inode/size/mtime identity within the request, and spawn with an argument array, `shell:false`, pipe stdin/stdout/stderr and a separate POSIX process group. Do not place source text, credentials or caller questions in argv.
- Run in a new private temporary directory, never the workspace or a parent of it. Do not use add-dir, session resume, permission handlers, browser/IDE integration or user-supplied extra arguments. Remove the temporary directory after all outcomes.
- Use safe mode, restricted mode, empty setting sources and explicit settings disabling hooks/connectors. Disable skills/commands, session persistence and Chrome. Deny file, shell, agent and network tools, set `dontAsk`, use an empty built-in tool list and strict empty MCP configuration. Node reads authorized context; Claude has no source-reading tool.
- Validate every streaming init: version, dontAsk mode, no MCP/skills and no executable tools. Only the CLI's schema-return `StructuredOutput` tool is accepted. The locally observed three built-in data plugins are explicitly recognized by exact name, builtin path and builtin source; external/unknown plugins fail closed. Any observed hook/task/agent event, forbidden tool request or permission denial aborts the process and rejects output.
- Use an environment allowlist and a fixed system-only child PATH, excluding project/package-manager binary directories. Native auth may use the real home/keychain and the existing ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN or CLAUDE_CODE_OAUTH_TOKEN. Do not inherit NODE_OPTIONS, loader/preload paths, project variables, custom endpoint overrides, CLI configuration directories, telemetry or shell helper commands. Disable updater/nonessential traffic, CLI retries, structured-output retries, thinking and prompt history; output tokens are bounded.

These are enforced CLI capability/permission controls, not prompt-only requests. They prevent model-directed application reads/writes and arbitrary tools. The installed executable, its recognized built-ins, operating system, authenticated provider and administrator-managed policy remain trusted. This is not an OS sandbox against a malicious/replaced CLI or hostile administrator; managed policy can affect startup behavior outside model tool use. The adapter neither bypasses such policy nor claims it can contain arbitrary trusted native code. No application root is passed to the child. CLI authentication may refresh its own credential state outside the source workspace; no claim of a completely write-free operating system is made.

The stream guard rejects unsafe capabilities promptly, but an init event is not an OS attestation. A supported, trusted release and the fixed startup flags are required before any source transmission. There is no tool-enabled fallback when safety checks fail.

## Context, privacy and evidence

AI is disabled by default and requires explicit `ai.enabled` and nonempty `ai.permittedPaths`. `NODE_ENV=production` rejects the provider. Importing/factory construction never starts Claude or reads source. No runtime/browser RPC or HMR/hover analysis is added.

The input is the deterministic analyzer's base `Finding[]` plus `sourceHashes`. Node rereads only referenced files through the analyzer's public workspace access policy, intersecting source includes/excludes with AI permitted paths. Reapply the stricter AI path exclusions to canonical aliases. Mandatory workspace containment, inode/change checks and 256 KiB per-file restrictions are retained. The AI package therefore depends on analyzer via its public export, with synchronized TypeScript references; browser-safe core/inspector do not depend on AI.

Only supported script sources, exact one-based UTF-16 ranges and matching SHA-256 snapshots can be transmitted. Snippets must match current source, with the analyzer's 2,048-character truncation convention. Stale findings, missing hashes, duplicate IDs, fabricated ranges, excluded paths and over-budget context are rejected. Arbitrary extra fields, runtime values and input explanation strings are not serialized; the prompt contains normalized source facts, original confidence, source references, code snippets and `execution:not-evaluated`. Detailed AST findings additionally retain whitelisted subject/target relationships and lexical guards whose evidence ranges are checked against the same source snapshot; arbitrary detail/runtime fields are discarded.

AI-specific exclusions include credential/secret/token/password paths, tool configuration folders and non-script files. Whole allowed snapshots, questions, selected UI strings and returned text are scanned for common private-key/token/Bearer/credential-assignment/credential-URL patterns. A match rejects the request; no automatic redaction silently changes evidence. This is a conservative detector with false positives and false negatives, not a guarantee that all sensitive data can be recognized. Callers must restrict consent to safe paths and pass only deliberately selected public UI text, never form values or private DOM data. No browser input collection is introduced.

Source snippets, selected text and questions **are transmitted to the configured Claude provider**, not assumed to remain local. No repository-wide scan, adapter source logging or persistent cache is added. CLI/provider-owned retention follows their policies; no-session-persistence is not a guarantee that every external diagnostic or provider record is disabled. Source snapshots are rechecked before accepting a result and between retries; a changed source rejects the explanation. This does not provide an atomic project snapshot or prevent another developer from changing a file concurrently.

## Structured results and confidence

Use schema-constrained JSON via `--json-schema`, NDJSON `stream-json` and a strict Zod payload schema. CLI envelopes allow additional non-executable metadata for the pinned release, but required security/result fields are validated. Enforce byte/message limits before accepting output. Missing structured output, unsupported language, extra payload fields, unknown citations or invented text IDs fail validation.

The model returns Vietnamese behavior/business-logic/translation/limitation prose with evidence IDs and optional selected UI IDs. Node resolves IDs to the original deterministic evidence; the model cannot supply source locations or code evidence. No generated prose is promoted to VERIFIED merely for citing a real source. Non-UNKNOWN prose with supported citations is INFERRED; missing/unknown source evidence remains UNKNOWN. UI-only translation is UNKNOWN under the existing source-evidence contract. A translation only retains source citations whose snippets contain the original selected string. Schema/citation validation does not prove linguistic or business-semantic accuracy. Original source and UI strings are never replaced.

The existing AIProvider `explain(): Finding[]` contract remains; `explainDetailed()` adds resolved citations and measured usage. Input cache status is validated and stale evidence is rejected; generated results have a new timestamp and cache miss. AI explanations do not replace the original VERIFIED deterministic findings.

## Bounds, failures and lifecycle

Defaults: one active request/provider, global maximum four, eight waiting/provider (maximum 32), global queue maximum 32, one retry (maximum two), 1-second exponential retry delay capped at 5 seconds, 60-second request deadline (configuration maximum 300 seconds), 24 findings, eight files, 64 KiB total snapshot bytes, 24,000 supplied context bytes, 16,000 conservative supplied input-token ceiling, 2,048 output tokens, 40,000 total-token budget, 256 KiB stdout, 16 KiB stderr and 256 stream messages. Public values are validated and have upper bounds. Queue time, preparation, discovery, retry delays and inference share one deadline. Resource overruns reject rather than silently truncate context.

The supplied input ceiling uses UTF-8 bytes of prompt/system/schema as a conservative application-content estimate, not a model tokenizer or measurement of hidden CLI/provider framing. Requested output tokens, reported input/cache/output usage, retry reservations and two CLI turns bound work; accumulated reported usage includes failed attempts when available. Failed/aborted calls may omit usage. CLI internal retries and schema retries are disabled. Max-budget-usd is divided across allowed attempts, but the CLI's client estimate can overshoot and differs from billing. These are work/best-effort spend controls, not a hard invoice or whole-process memory guarantee.

Only rate limits and recognized transient network/overload failures retry. Authentication, billing/quota, invalid output, unsafe permissions, stale context, cancellation and resource errors do not. CLI errors are classified into stable actionable codes; raw stdout/stderr is never attached to public errors or logged. An auth-status success followed by an inference failure remains unavailable.

Cancellation/deadline/output-policy failure terminates the POSIX process group, escalates TERM to KILL after 200 ms and bounds pipe cleanup to 1.5 seconds. Queue cancellation releases listeners/slots. Child processes inheriting pipes are covered by the group; hostile native code that escapes its process group is outside the trust boundary. No shell cancellation command is interpolated.

Mocked integrations use actual OS subprocesses for the CLI protocol, while deterministic source analysis and source-policy enforcement remain real. Live authenticated model quality cannot be inferred from mocks. See [Phase 06 validation](../phase-06-validation.md) and [usage](../claude-code.md) for actual execution evidence and environment limitations.
