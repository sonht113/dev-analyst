# ADR 0007: Phase 05 — Static Code Analysis Engine

Status: accepted for the owner's explicit Phase 05 request. The prompt's `@devlens/analyzer` name is treated as the older identity used in phase prompts; the owner-confirmed DevAnalyst identity and existing `@devanalyst/analyzer` package are retained. No second analyzer package or framework integration is introduced. Editor navigation remains pending despite its former roadmap numbering.

## Decision and research

Implement a Node-only deterministic source engine using the pinned TypeScript Compiler API. [AST/program/symbol APIs](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API), [TypeScript module resolution](https://www.typescriptlang.org/docs/handbook/modules/reference.html) and [configuration paths](https://www.typescriptlang.org/tsconfig/paths.html) inform the implementation. This is analysis of a closed set of authorized source snapshots, not application execution or an AI explanation.

The existing workspace policy moves from the Vite package into analyzer, its Node owner. Vite retains a compatibility re-export and uses the same implementation. Canonical containment, mandatory sensitive exclusions, symlink/inode/change checks and 256 KiB source limits remain enforced. A new canonical-path method deduplicates aliases before import traversal. Moving the policy avoids an analyzer → Vite → analyzer dependency cycle; picomatch/types move with it. Zod validates public options and requests. Browser-safe analysis result types live in core; browser code does not import the Node engine.

The engine exposes `createStaticAnalyzer(options).analyzeDetailed(request)` and preserves `StaticAnalyzer.analyze(request): Finding[]` through an adapter that returns the existing validated contract without additional fields. Phase 04 instrumentation is unchanged. No analysis work is added to configureServer, HMR, hover handlers or the bridge protocol, and no new RPC is introduced.

## Closed source loading and binding

1. Validate bounded source references/options, cancellation and resource limits.
2. Read requested TS/JS/TSX/JSX sources through workspace policy. Traverse literal ESM imports/re-exports breadth-first, with canonical visited identities and explicit depth/attempt/file/byte limits.
3. Optionally preload explicitly permitted local JSON/JSONC config extensions. Use `getParsedCommandLineOfConfigFile` over an in-memory host, with source discovery disabled. No Vite/TypeScript plugin code is loaded. Package/absolute config extensions are unsupported, configuration cycles are diagnosed, and shared ancestors are loaded once.
4. Preload guarded module candidates and call TypeScript's `resolveModuleName` over those cached paths. Explicit aliases override path mappings; inline mappings override corresponding config mappings. Only permitted workspace targets can become source modules. Bare external packages are represented as external graph nodes, not read from node_modules.
5. Build a TypeScript Program/TypeChecker with no default libraries, no emit, and a host that returns only preloaded AST/text. Malformed source is excluded before semantic binding. App/config functions, imports, getters, JSX, decorators, eval and subprocesses are never executed by analysis.

The result records hashes for actual valid source modules. Configs and additional authorized resolution snapshots count toward read metrics/limits. The engine rereads snapshots on each request; it is not a persistent cache or an atomic repository snapshot. A hash identifies the analyzed contents, not a promise that files cannot change afterward.

## Findings and graph semantics

Every detailed finding includes the existing confidence/evidence/timestamp/cache contract plus a discriminated `detail`, source subject ID, lexical conditions, trace contexts and `execution: not-evaluated`. `cacheStatus: miss` describes this fresh request. Source positions are one-based UTF-16 coordinates, with exclusive ends. Snippets are bounded to 2,048 characters and retain the actual source range. There are no invented endpoints or source destinations.

- **VERIFIED**: a source-level construct/reference is directly present, or a function/ESM alias resolves to a declaration under the loaded configuration. This does not prove execution, reachability, actual network requests, current state, computed CSS or runtime module replacement.
- **INFERRED**: naming conventions for custom hooks or a class render method without an established React base, possible method dispatch, component callback props, conditional handler candidates, a map-returning component candidate, or dynamic API/navigation expressions. Literal destination/endpoint fields remain null when evaluation would be required.
- **UNKNOWN**: unresolved/external implementations, mutable/dynamic callable targets, type-only value references, unsupported CSS/switch fallthrough control, opaque props/spreads, inaccessible sources or a resource boundary. Unknown targets never receive invented declaration locations.

Components include named/default exports, common memo/forwardRef shapes, lexical props and JSX usage. Props and render relationships describe source expressions, not effective runtime values. Simple `if`/ternary/logical/nullish/loop guards retain their original expression and polarity. Early-return guards are recognized only for simple terminating preceding statements; a containing if is not falsely treated as a preceding negative guard. Class/CSS visibility is unknown; native hidden/disabled, ARIA and style expressions remain distinct. ARIA does not itself enforce native disabling or visual visibility.

Handler traces resolve local functions, immutable aliases, imported/re-exported functions and useCallback bodies using checker symbols. Name shadowing and observed writes prevent false global/constant binding assumptions. JSX callback props are candidate edges, even when only one loaded parent supplies them, because runtime instance choice is not established. Parent relationships require the relevant parent entry module to be loaded; analyzing a child file alone does not scan all workspace importers. Uncalled nested functions keep source facts but receive no trace from an enclosing handler.

React state/reducer bindings, inherited class setState calls, known hooks and effect registrations are detected. Custom hook naming is inferred. Source references to React Router/TanStack router bindings/links, native navigation, fetch, Axios methods/created clients and known browser scheduling/storage APIs are recognized. Service wrappers are traced through their actual source to fetch/Axios calls. Endpoint expressions are not evaluated or substituted across arbitrary parameters; Axios baseURL and path stay separate literals. Unknown object spreads/computed/overwritten request options do not become guaranteed HTTP methods. Unclassified calls retain unknown effects rather than being guessed as API calls by name.

The bounded graph has module/component/function/element/call/external nodes and import/contains/render/handler/call/callback edges. Contains edges mean source containment, not invocation. Trace contexts carry separate confidence and source paths; source-level API existence can be verified while a caller path remains inferred. Import identities are visited once; recursive call edges remain visible while traversal stops. Multiple-parent candidates are bounded, trace depth is bounded and repeated trace contexts per finding are capped at eight.

## Limits and scope

Defaults: 64 snapshot files, 2 MiB total snapshot bytes, 100,000 AST nodes, 2,048 graph nodes, 4,096 edges, 1,000 findings, depth 12, 1,024 resolution attempts, 2,500 ms cooperative deadline, 100 diagnostics, 128 literal imports/module, 64 source roots and 16 lexical guards/finding. Per-file reads remain capped at 256 KiB. Configuration extension depth is eight; public limits have validated upper bounds. Cancellation/time checks occur around I/O and during traversal, but cannot preempt a single synchronous TypeScript operation or an OS filesystem call. This is not a hard real-time/process-memory sandbox.

`completion: complete` means the bounded pipeline finished, not that every behavior is understood. Unknown findings may remain in a complete result. Missing sources, unsupported discovery/config, parse errors and work cutoffs produce partial diagnostics; cancellation is distinct. Partial results never claim omitted work was checked.

This is not a full control-flow/dataflow/interpreter engine. Path feasibility, argument substitution, arbitrary mutation/aliasing, callback scheduling/cleanup timing, dynamic imports/requires, package runtime exports, getters/proxies, full CommonJS dependency resolution and CSS cascade analysis are not established. Semantic application type errors are not a full tsc validation gate. No additional router/framework integration is implemented; recognition of source calls is separate from runtime support. Static source evidence may contain literals from authorized files; mandatory file exclusions do not redact every secret embedded in otherwise allowed code. Results stay local; later AI/provider transmission requires separate consent and enforcement.

Tests use actual workspace files, public package imports, TypeScript binding, and a real browser selection passed to the Node engine. Application source containing file writes/throws stays unexecuted. The complete React + Vite product, inspector analysis display/RPC, AI, persistent cache and editor opening remain separate work.
